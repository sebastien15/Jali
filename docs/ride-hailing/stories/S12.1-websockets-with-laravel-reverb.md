## User story
**As a** developer,
**I want** ride status, driver location and new requests pushed over WebSockets,
**so that** updates are instant and battery/data usage drops versus polling.

## Acceptance criteria
- [ ] Private channels `ride.{id}` (rider + assigned driver) and `driver.{id}` with Sanctum auth.
- [ ] Events: ride status changed, driver location, new dispatch, dispatch withdrawn.
- [ ] Polling remains as automatic fallback when the socket is down.
- [ ] Load test: 2,000 concurrent connections on one VPS.
- [ ] Passes the UX quality checklist (`docs/ride-hailing/UX_QUALITY_CHECKLIST.md`)
- [ ] Routes inside `auth:sanctum` + `permission:<x>`, ownership checked in the controller, feature tests added
